Source: 拥有输入队列和输出队列，都是存放帧；读取（从文件等）一帧数据后放入输入队列，输入队列的frame被用完后放入输出队列，循环往复，因此循环中的frame数量是固定的，一般设置为4。Source读数据帧是通过向线程池添加任务，并且Source有一个内置任务成员函数对象用于随时添加到线程池。至于，是谁向线程池添加读取下一帧的任务以及何时添加，1）Source构造函数添加4次任务（因为循环中的frame就是4个）；2）其他类(就是Sink类)每次从Source的输出队列拿到一帧数据并处理完后，需要将frame放回Source的输入队列，放回的动作会自动向线程池添加读取下一帧任务（Source接口实现）

Sink: 作用就是不停地拿Source读取的frame，因此是由定时器驱动的。总的来说Source和Sink的工作模式就是Sink每隔指定的时间间隔从Source拿一帧数据并通过RTP发送，发送完将frame放回Source的输入队列，放回的同时自动向线程池放入一个读取任务，线程池的线程被唤醒开始读取下一帧放入Source的输出队列。既然Sink是定时器间隔不停地读取-发送-读取-发送，那么什么时候开始发送？因此发送的控制交给Session和RtpInstance
